# x402 pay-per-call (experimental, testnet-only, OFF by default)

## What it is

[x402](https://x402.org) is an HTTP-402-based payment standard. With it enabled, a caller with **no API key** can pay a small per-call price (USDC) for the verification endpoints. It is an alternative to API keys, not a replacement.

**Status: experimental.** Built against the official `x402` Python package (v2 protocol; tested with 2.28.0) and exercised only with a *fake in-process facilitator*. **No payment has been tested with real funds, not even testnet funds.** The one test that would contact the public testnet facilitator is written but skipped by default.

Honest market note: x402 volumes are small today. This is an option the owner can switch on, not a revenue claim.

## Design

| Topic | Behaviour |
|---|---|
| Default | **Off.** With `AGENTVERIFY_X402_ENABLED` unset/`0`/`false`, the middleware is a direct pass-through; behaviour and tests are unchanged, and the `x402` package is not imported. |
| Paid routes | `POST /verify`, `POST /verify/batch`, `POST /verify/signed` only. Not `/health`, `/pricing`, docs/OpenAPI, `/receipts/*`, `/ready`, `/payments/preview`, or the remote MCP mount (`/mcp` stays API-key only). |
| API key | A request carrying an `X-API-Key` header always takes the unchanged API-key path: a valid key is served free and bypasses payment; an invalid key is 401 (no payment fallback). Existing auth, rate limits, quotas, receipts and idempotency are untouched. |
| No key, no payment | `402` with the x402 requirements in the `PAYMENT-REQUIRED` header (base64 JSON; scheme `exact`, network, USDC asset, amount, pay-to). |
| Payment present | Header `PAYMENT-SIGNATURE` (v2). It is verified through the facilitator, the route runs, and the payment is **settled only if the route returned HTTP 200**. The settlement result is returned in `PAYMENT-RESPONSE`. The v1 `X-PAYMENT` header is not accepted (a v1-only client just receives a fresh 402). |
| Price | Default `0.001` USD paid in USDC (`1000` atomic units, 6 decimals), via `AGENTVERIFY_X402_PRICE` (0 < price ≤ 10, at most 6 decimals). |
| Batch rule | **One price per HTTP call, regardless of batch size** (the 64 KiB body cap bounds it). Set the price with that in mind. |
| 422 / any error | A request that returns 422 (or any non-200) is **not charged**: nothing is settled and the proof is released so it can be reused for a valid request. |
| Fail closed | Facilitator unreachable or erroring during verify or settle: `402` (or `503` if the facilitator cannot be reached to initialise). Never a free pass. The first paid request after an outage retries initialisation. |
| Request path | `body cap (413)` → `x402 gate` → `API-key middleware` → route. A verified payment marks the request via a server-side ASGI scope flag that clients cannot set, and the API-key middleware then skips key checks for that one request. |

### Replay protection and accounting

- A payment proof is single-use **per AgentVerify process**: a hash of the `PAYMENT-SIGNATURE` header and a hash of the payer+nonce from the payload (EIP-3009 `authorization`) are recorded. A repeat gets `402` with `{"error":"payment_already_used"}` and fresh requirements, and never reaches the facilitator.
- **Honest limit:** this registry is **in-process memory**. It is lost on restart and not shared between workers or instances (the app is documented single-worker). No existing durable store was reused. The facilitator and chain (the EIP-3009 nonce) remain the durable double-spend protection; this guard stops one proof buying a second *response*. A durable shared store is an owner/engineering follow-up before real money.
- The registry holds only one-way hashes (never headers or payloads), is capped at 100,000 entries, and consumed entries expire after 24 h.
- Payment reference: a successfully settled response carries `X-AgentVerify-Payment-Ref: <network>:<transaction>` (and the package's `PAYMENT-RESPONSE`). It is deliberately a **response header, not a body field**: signed receipts must keep exactly the keys `payload, algorithm, public_key, signature` (both `verify_receipt.py` and `/receipts/check` reject extra keys), so the receipt body and `verify_receipt.py` are unchanged.
- A global cap on payment-bearing requests (default 120/min, `AGENTVERIFY_X402_MAX_VERIFY_PER_MINUTE`) returns `429` so junk payments cannot hammer the facilitator.
- Payment headers and payloads are never logged or stored; the only x402 log lines are fixed strings.

## Configuration (environment variables)

| Variable | Default | Meaning |
|---|---|---|
| `AGENTVERIFY_X402_ENABLED` | off | `1`/`true` enables. Empty/`0`/`false` = off. Any other value refuses to start. |
| `AGENTVERIFY_X402_PAY_TO` | none | **Required when enabled.** Public receiving address `0x` + 40 hex (not all zero). Never commit it; never put a private key anywhere. |
| `AGENTVERIFY_X402_NETWORK` | `eip155:84532` | Base Sepolia **testnet**. Only `eip155:84532` and `eip155:421614` (Arbitrum Sepolia) count as testnets; any other network is treated as mainnet. |
| `AGENTVERIFY_X402_PRICE` | `0.001` | USD per call, paid in USDC. |
| `AGENTVERIFY_X402_FACILITATOR_URL` | `https://x402.org/facilitator` | The package's documented public **testnet** facilitator. `https` only (plain `http` only for loopback); no credentials/query in the URL. |
| `AGENTVERIFY_X402_ALLOW_MAINNET` | unset | Must be exactly `1`, **and** a non-default facilitator URL must be set, to use a mainnet network. |
| `AGENTVERIFY_X402_MAX_VERIFY_PER_MINUTE` | `120` | Global cap on payment-bearing requests. |

Safety rails (all enforced at startup via the deployment-config check and again per request, with value-free error messages):
refuse to start if enabled with a missing/malformed `PAY_TO`; refuse any non-testnet network unless `ALLOW_MAINNET=1` **and** an explicit non-default facilitator URL are both set (the public facilitator is a testnet service, not a mainnet default); fail closed if the facilitator is unreachable; never log payment headers or payloads.

Dependencies: `x402[evm]` (the EVM extra pulls in `web3`/`eth-account`, which the package imports even for the seller side). The `fastapi` extra is not needed; its middleware only needs `fastapi`/`starlette`, which are already required (the package requires `fastapi>=0.162`).

## Testing

```
python -B tests_x402.py          # fake facilitator, no network, no funds, no keys
```

Optional, **not run in this task** and skipped by default: set `AGENTVERIFY_X402_RUN_TESTNET_INTEGRATION=1` to make one read-only call to the public testnet facilitator's `/supported`. It needs network but no funds and no keys.

## Owner steps still needed before taking real payments (none of these have been done)

1. Choose a receiving address you control (public address only is ever configured here).
2. Choose a production facilitator for mainnet (the default URL is testnet-only) and review its terms and fees.
3. Decide the price (and whether a flat per-call price for batches is acceptable).
4. Decide hosting (the app is single-worker, the replay registry is in-process, TLS and public exposure are your call) and whether to add a durable shared replay store.
5. Run a testnet end-to-end with a real testnet client and faucet funds, then review before any mainnet flag is set.
6. Legal/tax/terms review for charging money.
